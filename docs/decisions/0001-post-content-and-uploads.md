# ADR-0001: Посты, Markdown и загружаемые фотографии

Дата: 2026-10-09
Статус: accepted
Основание: запрос пользователя на CRUD постов; технический выбор в рамках реализации.
Задача: [управление постами](../agent/tasks/2026-10-09-post-management.md).

## Решение

Используем существующие `posts` и глобальные `post_tags`. Legacy notes сохраняется отдельно. Новые посты публикуются с private по умолчанию; автор явно выбирает public. Персональная лента содержит собственные published, общая — public/published. DELETE переводит в draft без удаления содержимого; редактирование draft не публикует его повторно.

Markdown хранится исходником. Goldmark разбирает AST на сервере: HTML, внешние изображения и ссылки кроме абсолютных HTTP(S) отклоняются; примеры HTML внутри code blocks остаются текстом. Клиент использует react-markdown без raw HTML, с ограниченными URL. MDXEditor работает без JSX-плагинов, выполнения кода и обработки HTML. Визуальный редактор загружается отдельно от основной страницы.

Фотографии сохраняются в `post_uploads` PostgreSQL (bytea), отдельно от архивного CAS, запись в который остаётся обязанностью worker. Это позволяет сохранить атомарное присоединение фото к посту и проверять права при каждом чтении без публичных файловых путей или bearer-токенов в URL. В браузере защищённые фотографии загружаются API-клиентом и показываются через временный Blob URL, освобождаемый после использования.

Сервер декодирует JPEG/PNG/GIF/BMP/WebP и перекодирует в JPEG или PNG: удаляет метаданные и приписанное содержимое; для GIF сохраняет первый кадр. SVG и неизвестные форматы запрещены. Лимиты: 10 МиБ вход/результат, 20 Мп, сторона до 10000 пикселей, 32 фото на пост, 256 МиБ сохранённых изображений на пользователя. Одновременно нормализуются максимум два фото на процесс. Загрузка — отдельный JSON-запрос с base64 (лимит тела 14 МиБ), присоединение — по проверенным ID владельца. Неиспользованные загрузки старше 24 часов удаляются при следующей загрузке этого пользователя; отдельного фонового сборщика пока нет.

## Альтернативы и последствия

Файловое/S3-хранилище потребовало бы нового lifecycle публикации, cleanup и согласования с worker/CAS. Для ограниченного первого среза PostgreSQL проще в эксплуатации и резервировании. Цена — рост БД и base64 overhead. Перед расширением квот/масштаба перейти на выделенное blob-хранилище с тем же ACL, добавить thumbnails и фоновую очистку. Сейчас сетка использует нормализованные изображения полного размера; анимация GIF не сохраняется.
