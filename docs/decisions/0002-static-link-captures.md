# ADR-0002: фоновые статические копии ссылок

Статус: accepted. Дата: 2026-10-13.
Основание: пользователь запросил DOM после рендера, без выполнения скриптов при просмотре, независимый эскиз и фоновую обработку. Технический выбор хранения и изоляции делегирован в рамках задачи.

## Решение

`post_captures` хранит опции, UUID ревизии, состояние pending/ready/failed и manifest. River `post.capture` ставится в той же SQL-транзакции, что и пост. Очередь capture имеет одного исполнителя, до трёх попыток. Worker пишет immutable CAS, затем одним UPDATE публикует все запрошенные результаты только для текущей ревизии опубликованной ссылки. Повтор после завершения ничего не делает. До завершения URL копии и эскиза пусты. Изменение URL/опций/типа сбрасывает результаты; изменение только названия/тегов/видимости сохраняет готовую копию. Повторное сохранение failed-ссылки запускает новую попытку.

Chromium живёт в контейнере без прямого egress и без БД/файлов приложения. Все GET-загрузки выполняются отдельным авторизованным шлюзом: HTTP(S), стандартные порты, публичный IPv4; DNS проверяется, TCP подключается к проверенному IP без повторного DNS, TLS проверяет исходное имя. IPv6, private/loopback/link-local/metadata/reserved, нестандартные порты, credentials в URL запрещены. Каждый HTTP-редирект (до пяти) разрешается до передачи ответа браузеру: Playwright может не перехватить следующий redirect request. Service workers и WebSockets запрещены, POST и пользовательские cookies/Authorization исходному сайту не передаются. Шлюз не имеет сети БД. Реальная сетевая граница обязательна; запуск capture на обычном хосте не эквивалентен Compose.

После DOMContentLoaded ждём network idle до 8 секунд, выполняем ограниченную прокрутку для lazy-контента и возвращаемся наверх. Эскиз — PNG 800×600. Сохраняем DOM, открытые shadow roots, доступные canvas, текущие значения полей и загруженные CSS/image/font. Удаляем скрипты, обработчики событий, активные embeds, redirects, формы и внешнюю навигацию. CSS url/import переписываются на ссылки manifest. Копия открывается через JSON API в iframe `sandbox=""`, с opaque origin, без allow-scripts/allow-same-origin; CSP запрещает сеть, скрипты, frames, формы. Ресурсы в окне преобразуются в data URL, поскольку opaque frame не может читать blob URL приложения. Отдельного публичного HTTP-origin архивов не создаётся.

## Хранение и CSS

Только worker записывает CAS: SHA-256 содержимого, путь `<первые два символа>/<hash>`, без пользовательских компонентов пути. API получает volume read-only; каждое чтение bundle/эскиза проверяет текущие права поста. Общие файлы не дают общего доступа: manifest другого приватного поста недоступен.

Manifest содержит иерархию HMAC-SHA256(origin), хэши сегментов пути, query-вариант и hash содержимого. Worker публикует её также физически в `BLOB_ROOT/sites/` через hard links на CAS: HTML имеет расширение `.html`, стили — `.css`; одинаковые файлы занимают один inode. Все компоненты пути валидируются как хэши, пользовательские пути не передаются файловой системе. Соль — отдельный сервисный CAPTURE_TOKEN (не auth-ключ). Кэш исходных CSS шлюза — отдельный volume `capture-cache`, до 64 МиБ, хэши origin/path/query в именах. Он переживает рестарт. Одновременные загрузки объединяются, в течение суток файл повторно не скачивается; затем используется conditional GET с ETag/Last-Modified, если сервер их предоставляет. Изменившийся CSS становится новой immutable версией и не меняет старые снимки.

Предложенную схему «только path без GET» расширяем query/content-версией: `/page?id=1` и `/page?id=2`, а также `style.css?v=1` и `?v=2` не должны перезаписывать друг друга. HTML также хранится по содержимому в CAS, а не под одним перезаписываемым именем.

## Границы обещания

Это гостевой статический снимок, а не интерактивное зеркало. Требующие входа/CAPTCHA сайты, closed shadow DOM, tainted canvas, видео/iframe, бесконечная прокрутка и произвольно поздние изменения не гарантируются. Только IPv4. Сохранённая копия может отличаться при другом размере окна. Некоторые отсутствующие ресурсы/встроенные блоки отмечаются предупреждением; это не полная автоматическая оценка визуального сходства.

Лимиты: один браузер за раз, 75 секунд на capture, 250 запросов, ресурс до 5 МиБ (также после распаковки), суммарно до 24 МиБ загруженных ответов, DOM до 5 МиБ. Worker ограничивает ответ 48 МиБ. При ошибке основного документа результата нет. Статические CSS/data URL разворачиваются в памяти клиента с ограничением размера.

CAS сохраняет и непривязанные blobs при сбое/смене ревизии. Сборка мусора по ссылкам, долгосрочные пользовательские квоты и ручной refresh готовой копии остаются отдельными задачами; файлы не удаляем до их реализации.

## Проверка

Unit: URL/IP/DNS, CSS reuse и persistent cache, удаление активного HTML, переписывание CSS. Integration: River-транзакция, изменение URL во время захвата, idempotence, ready/failed/retry, независимые опции и ACL. Browser: форма, polling, data URL стили/изображения, sandbox, запрет внешней сети, mobile. Container smoke: реальный Chromium, JS DOM/shadow, 800×600, CSS reuse, private/metadata/IPv6/subresource/redirect и отсутствие прямого egress. Проверки включены в CI. Полная матрица всех сайтов не заявляется.

Технические основания: [Playwright network](https://playwright.dev/docs/network), [ограничение route на HTTP redirects](https://playwright.dev/docs/api/class-page#page-route).
