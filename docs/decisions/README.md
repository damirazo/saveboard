# Архитектурные решения (ADR)

Создавай ADR при существенном выборе: модель данных, граница сервиса, API/auth-контракт, хранение архивов, смена зависимости или стратегия миграции. Для локального рефакторинга достаточно плана задачи или описания изменения.

Файл: `NNNN-short-name.md`, следующий свободный номер. Используй [шаблон](TEMPLATE.md). Здесь добавляй ссылку, название и статус. Не объявляй существующую архитектуру заново принятой без основания: у неё пока статус предложения, а текущая реализация может отличаться.

Статусы: proposed, accepted, superseded, rejected. В accepted укажи основание решения: явный ответ пользователя или делегированный технический выбор в рамках задачи. При замене сохраняй старое решение со ссылкой на новое.
