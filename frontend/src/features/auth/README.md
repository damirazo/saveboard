# Авторизация и ленты Saveboard

Публичная лента `/` доступна гостям и авторизованным пользователям. После входа по username/email и паролю приложение переводит пользователя на `/feed`. Этот маршрут требует сессию; `/login` перенаправляет вошедшего пользователя на `/feed`. Авторизованный пользователь переключается между `/feed` и `/` вкладками «Моя лента» и «Публичная лента», сохраняя профиль и меню. Выбранная лента сохраняется в URL при перезагрузке. Старый `/preview/member` перенаправляет на защищённую ленту.

Login подключён к `/api/v1/auth/login`. Access JWT и refresh-токен хранятся в `sessionStorage`: переживают перезагрузку в текущей вкладке, но не закрытие вкладки. Пароль не сохраняется. При восстановлении вызывается `/api/v1/auth/me`. API пока возвращает только ID пользователя и сессии, поэтому в профиле отображается введённый login.

Регистрация подключена к `POST /api/v1/auth/register`: username, email, пароль и клиентское подтверждение пароля. После успеха сессия сохраняется и открывается `/feed`. Подтверждение пароля на сервер не отправляется. Занятые username/email, неверные данные, сетевые ошибки и временная недоступность показываются в форме; данные сохраняются для исправления. Отправка блокируется на время запроса. Вошедший пользователь с `/login` и `/register` перенаправляется в личную ленту. Аккаунт активен сразу; подтверждение email пока не реализовано, адрес не помечается проверенным.

Общий API-клиент добавляет `Authorization: Bearer` только к запросам `/api/` своего origin. Перед запросом при остатке жизни access-токена менее 30 секунд выполняется refresh. После 401 выполняются ротация и один повтор исходного запроса. Одновременные запросы используют общий refresh; новая пара токенов сохраняется целиком. Отозванная/истёкшая сессия удаляется, временные сетевые ошибки сохраняют её для следующей попытки. Выход отзывает сессию на сервере и очищает локальное состояние и query cache.

Текущий сервер принимает refresh-токен в JSON, поэтому он доступен JavaScript. Для перехода на HttpOnly cookie потребуется изменить серверный контракт. Сессии вкладок изолированы; синхронизация между вкладками не реализована.

Публикации, поиск, фильтры и сортировка подключены к posts API. Создание доступно активным пользователям, редактирование и перевод в черновик — владельцу; сервер проверяет права отдельно от UI. Избранное и архивы пока показывают состояние будущего раздела. OAuth-кнопка остаётся явно обозначенной заглушкой.

Общая оболочка находится в `components/layout/app-shell.tsx`, меню — в `sidebar.tsx`. Демонстрационная нижняя навигация удалена. `AuthPage` переиспользуется для входа и регистрации через `mode` и асинхронный `onSubmit`.

Проверки: `pnpm check`, `pnpm test:e2e` (при необходимости `PLAYWRIGHT_CHANNEL=chrome`). Unit-тесты проверяют хранение, восстановление, Bearer, совместную ротацию, повтор запроса и отзыв; браузерные тесты используют подменённые ответы API.
