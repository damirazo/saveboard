# Frontend

Применяется вместе с корневым `AGENTS.md` ко всему `frontend/`.

- React/TypeScript strict, Vite, TanStack Router/Query. Маршруты — `src/app/router.tsx`, страницы — `src/features/`, общие компоненты — `src/components/`.
- Перед UI-изменениями прочитай [соглашения компонентов](src/components/README.md); перед auth — [описание сессии](src/features/auth/README.md).
- Используй существующие компоненты и варианты. Палитра/размеры — `src/styles/tokens.css`, общие стили блоков — `src/styles/components.css`. Не копируй стили общего компонента в отдельную страницу.
- Сохраняй доступность: подписи полей, клавиатурную навигацию, видимый фокус, состояния загрузки, ошибки и пустые результаты. Проверяй затронутый UI на мобильной и desktop ширине.
- API вызывай через `packages/api-client`. `schema.d.ts` генерируется; после изменения сервера используй корневую `pnpm api:generate`. Локальная генерация frontend читает только имеющийся снимок OpenAPI.
- Сессия сейчас хранится в `sessionStorage`; сохраняй объединение одновременных refresh, ограничение повторов и очистку query cache при выходе. Переход к HttpOnly cookie требует согласованного изменения backend-контракта.
- Клиентский route guard не заменяет серверный ACL. Не передавай Bearer-токен внешнему origin.
- Ленты и CRUD используют posts API. Демо-посты остаются тестовыми fixtures; избранное и архивы ещё не подключены. Вход и регистрация работают через API, OAuth UI пока заглушка; API OAuth и его интерфейс — разные уровни готовности.

## Проверки из корня

- Статические проверки, unit-тесты и сборка: `pnpm --dir frontend check`.
- Маршруты, формы, сессии и пользовательские сценарии: `pnpm test:e2e` (нужен браузер Playwright).
- Если используется установленный Chrome в PowerShell: `$env:PLAYWRIGHT_CHANNEL='chrome'`, затем `pnpm test:e2e`.
- Подменённые ответы в browser-тестах проверяют UI; отдельно укажи, когда реальный backend не проверялся.
