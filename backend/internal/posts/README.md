# Модель постов

`Post` хранит UUID, автора (`users.id`), даты, статус (`draft`, `published`,
`archived`), тип (`note`, `link`, `photo`) и видимость (`public`, `unlisted` —
по ссылке, `friends`, `private`). По умолчанию пост — приватный черновик.

Данные типов вынесены в `post_notes` (текст), `post_links` (URL) и
`post_photos` (несколько фотографий с отдельными UUID и URL). Заметка и ссылка
используют UUID поста как первичный ключ. Составные внешние ключи запрещают
добавлять данные другого типа. Черновик может существовать без содержимого;
проверку полноты перед публикацией выполняет `Service.Save`.

Общие теги `Tag` хранятся в `post_tags`: UUID, глобально уникальный `name`
(с учётом регистра), `title`. Связь многие ко многим — `post_tag_links`;
на уровне схемы пост может не иметь тегов, но API требует от 1 до 20. Существующие `notes`, `tags`, `note_tags` относятся
к прежней модели заметок и не изменяются этой миграцией.

Связи Bun: `Note`, `Link`, `Photos`, `TagLinks.Tag`. Создавайте пост и его
содержимое в одной транзакции. Даты и UUID назначает PostgreSQL; изменения
поста, содержимого и связей с тегами обновляют `posts.updated_at`. Удаление
поста непосредственно в SQL каскадно удаляет содержимое и связи, сохраняя общий справочник тегов. HTTP DELETE только переводит пост в draft.

## API управления

Миграция `00005_post_management.sql` добавляет название, порядок фото и защищённое хранилище загрузок. Применить через `pnpm --dir backend migrate` из корня с настроенным `DATABASE_URL` либо штатным Compose migrator.

- `GET /api/v1/posts?scope=public|mine&type=note|link|photo&q=...&page=1&size=10&sort=new|old`: published-посты, total, фильтр и поиск. `q` — буквальная подстрока без учёта регистра в названии или тексте заметки, без поиска по тегам. `include_tags` и `exclude_tags` — списки UUID через запятую (до 20 в каждом): все включённые теги обязательны, любой исключённый убирает пост. Пустые списки не ограничивают выдачу, пересечение списков даёт пустой результат. Параметр `author` ограничивает выдачу по username без учёта регистра. Фильтры применяются до count и пагинации; неизвестный UUID включения не даёт результатов, неверный UUID возвращает 422. `mine` требует сессию; выдаёт только собственные посты. Публичная выдача не включает private/unlisted/friends/draft/archived.
- `GET /api/v1/posts/{id}`: автор или public/published; иначе 404.
- `POST /api/v1/posts`, `PUT /api/v1/posts/{id}`: title, type, visibility (private/public), tags (`id` существующего либо пустой `id` и `title` нового), markdown/url/photo_ids по типу. Название до 200 символов, Markdown до 100 КБ. Только активный пользователь; PUT — только автор. Подтипы, теги и фото меняются транзакционно, тип можно поменять.
- `DELETE /api/v1/posts/{id}`: только автор, перевод в draft; данные и фото сохраняются, обе ленты исключают пост. PUT черновика не возвращает его в published.
- `GET /api/v1/post-tags?q=...`: доступный гостям autocomplete по началу title/name, без учёта регистра, до 12 результатов, полные совпадения первыми. `%`/`_` считаются буквальными символами. Создание тегов происходит вместе с сохранением поста; транслитерация кириллицы, lowercase, дефисы; совпавшие title переиспользуются, коллизии name получают числовой суффикс.
- `POST /api/v1/photos`: JSON `{ "data": "<base64>" }`, активная сессия, нормализация содержимого; возвращает id/url. Присоединить можно только собственный файл, не занятый другим постом.
- `GET /api/v1/photos/{id}`: бинарный PNG/JPEG; доступен владельцу либо посетителю public/published поста, `Cache-Control: no-store`, `nosniff`. При draft или private публичный доступ прекращается.

Политика Markdown/фото, лимиты и компромиссы: [ADR-0001](../../../docs/decisions/0001-post-content-and-uploads.md). Раздел черновиков в UI остаётся будущей задачей.

## Копии ссылок

Независимая опция `index_rag` (false по умолчанию) включает фоновое извлечение/очистку текста и индексацию в Qdrant. View возвращает `index_rag` и `rag_state` (pending/ready/failed либо пусто). Миграция `00008_link_rag.sql`, устройство и очистка — [search README](../search/README.md). Выключение флага/смена типа/draft исключают активную генерацию сразу, внешние точки удаляются в фоне. Повторное сохранение failed с включённым флагом запускает новую попытку. Ошибка индексации не меняет результат копии/эскиза.

Миграция `00006_link_captures.sql`. В Write добавлены `save_copy` и `create_thumbnail` (false по умолчанию в форме), только для link. Сохранение поста и постановка `post.capture` выполняются в одной транзакции. View возвращает эти опции, `capture_state`, `capture_warning`, `copy_url`, `thumbnail_url`; URL результатов пусты до ready. Изменение URL/опций создаёт новую ревизию, устаревшая задача не публикуется. Failed можно повторить сохранением формы; простое изменение названия не пересоздаёт готовую копию.

- `GET /api/v1/posts/{id}/copy`: JSON bundle HTML+base64 resources, автор или public/published, иначе 404. HTML нельзя вставлять в DOM приложения; использовать opaque sandbox и CSP, как в frontend.
- `GET /api/v1/posts/{id}/thumbnail`: PNG, те же права; пока не готов или не запрошен — 404.

API монтирует BLOB_ROOT read-only. Worker должен иметь CAPTURE_URL, CAPTURE_TOKEN и доступ на запись к BLOB_ROOT. Без capture базовый CRUD работает; запрошенная обработка повторяется в фоне и может завершиться failed. Все ограничения и безопасность описаны в [ADR-0002](../../../docs/decisions/0002-static-link-captures.md).
