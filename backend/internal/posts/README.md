# Модель постов

`Post` хранит UUID, автора (`users.id`), даты, статус (`draft`, `published`,
`archived`), тип (`note`, `link`, `photo`) и видимость (`public`, `unlisted` —
по ссылке, `friends`, `private`). По умолчанию пост — приватный черновик.

Данные типов вынесены в `post_notes` (текст), `post_links` (URL) и
`post_photos` (несколько фотографий с отдельными UUID и URL). Заметка и ссылка
используют UUID поста как первичный ключ. Составные внешние ключи запрещают
добавлять данные другого типа. Черновик может существовать без содержимого;
проверку полноты перед публикацией выполняет `Service.Save`.

Общие теги `Tag` хранятся в `post_tags`: UUID, глобально уникальный `name`
(с учётом регистра), `title`. Связь многие ко многим — `post_tag_links`;
на уровне схемы пост может не иметь тегов, но API требует от 1 до 20. Существующие `notes`, `tags`, `note_tags` относятся
к прежней модели заметок и не изменяются этой миграцией.

Связи Bun: `Note`, `Link`, `Photos`, `TagLinks.Tag`. Создавайте пост и его
содержимое в одной транзакции. Даты и UUID назначает PostgreSQL; изменения
поста, содержимого и связей с тегами обновляют `posts.updated_at`. Удаление
поста непосредственно в SQL каскадно удаляет содержимое и связи, сохраняя общий справочник тегов. HTTP DELETE только переводит пост в draft.

## API управления

Миграция `00005_post_management.sql` добавляет название, порядок фото и защищённое хранилище загрузок. Применить через `pnpm --dir backend migrate` из корня с настроенным `DATABASE_URL` либо штатным Compose migrator.

- `GET /api/v1/posts?scope=public|mine&type=note|link|photo&q=...&page=1&size=10&sort=new|old`: published-посты, total, фильтр и поиск. `mine` требует сессию; выдаёт только собственные посты. Публичная выдача не включает private/unlisted/friends/draft/archived.
- `GET /api/v1/posts/{id}`: автор или public/published; иначе 404.
- `POST /api/v1/posts`, `PUT /api/v1/posts/{id}`: title, type, visibility (private/public), tags (`id` существующего либо пустой `id` и `title` нового), markdown/url/photo_ids по типу. Название до 200 символов, Markdown до 100 КБ. Только активный пользователь; PUT — только автор. Подтипы, теги и фото меняются транзакционно, тип можно поменять.
- `DELETE /api/v1/posts/{id}`: только автор, перевод в draft; данные и фото сохраняются, обе ленты исключают пост. PUT черновика не возвращает его в published.
- `GET /api/v1/post-tags?q=...`: авторизованный autocomplete по началу title/name, без учёта регистра, до 12 результатов, полные совпадения первыми. `%`/`_` считаются буквальными символами. Создание тегов происходит вместе с сохранением поста; транслитерация кириллицы, lowercase, дефисы; совпавшие title переиспользуются, коллизии name получают числовой суффикс.
- `POST /api/v1/photos`: JSON `{ "data": "<base64>" }`, активная сессия, нормализация содержимого; возвращает id/url. Присоединить можно только собственный файл, не занятый другим постом.
- `GET /api/v1/photos/{id}`: бинарный PNG/JPEG; доступен владельцу либо посетителю public/published поста, `Cache-Control: no-store`, `nosniff`. При draft или private публичный доступ прекращается.

Политика Markdown/фото, лимиты и компромиссы: [ADR-0001](../../../docs/decisions/0001-post-content-and-uploads.md). Раздел черновиков в UI остаётся будущей задачей.
