# Модель постов

`Post` хранит UUID, автора (`users.id`), даты, статус (`draft`, `published`,
`archived`), тип (`note`, `link`, `photo`) и видимость (`public`, `unlisted` —
по ссылке, `friends`, `private`). По умолчанию пост — приватный черновик.

Данные типов вынесены в `post_notes` (текст), `post_links` (URL) и
`post_photos` (несколько фотографий с отдельными UUID и URL). Заметка и ссылка
используют UUID поста как первичный ключ. Составные внешние ключи запрещают
добавлять данные другого типа. Черновик может существовать без содержимого;
проверку полноты перед публикацией должен выполнять будущий сервис постов.

Общие теги `Tag` хранятся в `post_tags`: UUID, глобально уникальный `name`
(с учётом регистра), `title`. Связь многие ко многим — `post_tag_links`;
пост может не иметь тегов. Существующие `notes`, `tags`, `note_tags` относятся
к прежней модели заметок и не изменяются этой миграцией.

Связи Bun: `Note`, `Link`, `Photos`, `TagLinks.Tag`. Создавайте пост и его
содержимое в одной транзакции. Даты и UUID назначает PostgreSQL; изменения
поста, содержимого и связей с тегами обновляют `posts.updated_at`. Удаление
поста каскадно удаляет содержимое и связи, сохраняя общий справочник тегов.

Видимость пока хранится как поле модели; проверка доступа должна быть
реализована в сервисе/API при добавлении операций с постами.
