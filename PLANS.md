# Планы задач

Для задачи с несколькими этапами, миграцией, изменением нескольких подсистем или продолжением в другом чате создай `docs/agent/tasks/YYYY-MM-DD-short-name.md` по [шаблону](docs/agent/tasks/TEMPLATE.md). Для небольшой локальной правки отдельный файл не нужен.

- Один план — один проверяемый результат. Название файла должно различать задачи одной даты.
- Зафиксируй запрос, границы, критерии приемки, исходные факты и существенные неизвестные до реализации.
- План должен позволять продолжить работу без истории чата: указывай пути, команды с рабочей директорией и наблюдаемый результат.
- Этапы помечай выполненными только по факту. Обновляй план после значимого этапа, уточнения пользователя и перед передачей работы.
- Статусы: `planned`, `in_progress`, `blocked`, `done`, `cancelled`. Для `blocked` укажи препятствие и что его снимает; для `done` — результат приемки и ограничения проверок.
- Ответы пользователя переносить в требования/решения с датой; устаревшие предположения убирать из активного контекста.
- Проверки записывай как «команда → результат → дата»; различай passed, failed и not run. Не переноси прошлый успех как результат нового запуска.
- Долгосрочные решения выноси в ADR; этапы продукта остаются в `docs/implementation-plan.md`. План задачи не дублирует roadmap.
- После завершения оставляй план в истории репозитория. В `docs/agent/context.md` держи только ссылки на актуальную работу и существенные итоги.
